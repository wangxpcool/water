# 快照保存与账户历史

本次变更涉及 `water-server` 和 `water-web`。启动新版本后，已有快照的账户分类、分组、标签、名称及汇总占位标记会保存到 `asset_snapshot_context`。旧数据库此前没有保存账户定义版本，因此首次升级只能以当前可用的定义建立历史基线，不能还原更早发生的分类变更。启动不会重新计算既有快照的金额。

## 新增账户的行为

- 新增账户不会向旧快照插入明细，也不会改变旧快照的总资产、负债和净资产。
- 新日期录入会显示启用账户，已有余额取自该日期之前最近一次快照；新账户金额为空，填入后才参与保存。
- 编辑已有日期会保留当时的账户，包括后来停用或移组的账户。需要补录新账户时，使用“添加到本次记录”明确选择。
- 历史上的汇总占位账户用 `is_subtotal` 标记。新建真实账户默认不带此标记，不再按账户代码相同就排除原有真实账户。例如原美股账户 100、新券商账户 20，合计为 120。
- 净资产变化包含账户新增、资金流入和流出，不是投资收益率。

## 保存与恢复

同日记录使用事务 PUT 更新，保存失败会回滚；收入、支出等录入台账未编辑的字段会保留。快照编辑保留原始明细及明细备注。标签调整与快照一并保存；默认金额和港币汇率由 config_dictionary 管理。旧版本浏览器里的全局调整会自动迁入字典中缺失的键，历史快照仍保留当期金额及汇率。

录入草稿按日期保存在当前浏览器。切换日期、刷新后可恢复；保存成功后清除该日期草稿。“放弃草稿”重新读取已保存记录。清理浏览器数据会丢失未提交草稿。

## 旧版人民币标识修正

美股账户实际按人民币录入，使用 ISO 币种代码 `CNY`。只修正账户、分组及其历史明细的币种标识，金额和原币金额均不换算。默认种子与初始化导入脚本也使用 CNY。

以下脚本仅用于原始数据全部以人民币录入的旧版数据库。已经启用美元券商账户后，不应再用它进行批量币种修正：

```powershell
python water-server/scripts/set-us-stock-cny.py water.db --backup-dir runtime-logs/backups
```

## IBKR 与嘉信分账

- 保留原美股分组（CNY 汇总），沿用原真实账户 ID 改名为 IBKR，默认币种改为 USD；嘉信另建 USD 真实账户。沿用 ID 让账户变化比较保持连续。
- 修改默认币种不是兑换操作：旧快照中的 CNY 金额、原名称和汇率继续保留，不能把旧金额直接改标成 USD。今日明细使用已读取的 IBKR 美元总净值，并只更新今日冻结定义；不回写历史。
- 新台账沿用上一期金额时会检查币种，不匹配则留空重新录入；币种定义不匹配的浏览器草稿不自动恢复。账户列表也不会将旧 CNY 余额标成 USD。
- 按用户选择，2026-10-20 嘉信直接按预计到账的 2,980 USD 计值（存储值为 2.98），备注标明尚未到账、属于估值。对应约 20,000 CNY 汇出款不再单列在途资产，原在途账户及分组已停用，避免重复计入；到账后核对并更新实际美元净值。
- `USD_CNY` 由金额与汇率配置管理，随快照冻结。用于核对的交叉汇率或估算汇率应在字典备注注明来源，不代表实时市场报价。
- 2026-10-20 经用户纠正，美元默认汇率及当日快照改按 USD/CNH 近似值 6.67 折算人民币，替代从旧港币汇率推算的 6.82783496。已备份数据库，仅定向修正当日冻结汇率并通过保存接口重新计算；历史快照及港币汇率 0.87 未改动。
- 本次只拆分今日数据，先前讨论的 1007 中银余额及历史美股重估仍未写入。业务核对假设不能自动覆盖历史原始记录。

## 验证

- Java 17：`mvn test`，包括停用/移组后编辑、重启不重算、新账户不污染旧快照、新旧美股账户累加、数据库写入失败回滚、标签调整持久化。
- 前端：`npm run build`。
- 浏览器在数据库副本上验证：首页图表、按日期切换、草稿恢复、同日保存保留原字段、显式补录新账户。
- 首页请求快照摘要；明细在展开或编辑时读取，列表每页显示 20 条。Chart.js 由 npm 本地打包。

更新后需重启后端，再刷新前端。测试环境可通过 `WATER_API_TARGET` 指定前端代理目标，默认仍为 `http://localhost:8080`。
